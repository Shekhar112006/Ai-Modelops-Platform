# M9 — Monitoring, Drift Detection & Deployment Metrics

## Overview

M9 adds Prometheus-based observability across the ModelOps API, model router,
model servers, and Celery task execution. It also adds statistical feature
drift detection and exposes operational metrics in the frontend Observability
page.

## Components

| Component | Endpoint / Port | Purpose |
|---|---|---|
| ModelOps API | `:8000/metrics` | HTTP request, error, latency and prediction metrics |
| Model router | `:8004/metrics` | Router HTTP and prediction outcome metrics |
| Production model server | `:8003/metrics` | Inference and drift metrics |
| Staging model server | `:8006/metrics` | Inference and drift metrics |
| Celery metrics exporter | `:8005/metrics` | Multiprocess Celery task metrics |
| Prometheus | `:9090` | Scraping, querying and time-series storage |
| Frontend | `:8080` | Observability dashboard and Prometheus proxy |

The model-server Docker image includes the reference dataset at:

`/app/ml/data/raw/demo_dataset.csv`

The reference data is generated by the demo workload and contains ten feature
columns (`feature_01` through `feature_10`).

## Metrics

### API and router

HTTP instrumentation records:

- modelops_http_requests_total
- modelops_http_request_errors_total
- modelops_http_request_duration_seconds
- modelops_predictions_total

The metrics middleware excludes `/metrics` scrapes and uses route templates
for bounded label cardinality.

### Model servers

Inference metrics:

- modelops_model_server_predictions_total
- modelops_model_server_inference_duration_seconds

Drift metrics:

- modelops_model_server_drift_checks_total
- modelops_model_server_drifted_features

### Celery

Worker metrics:

- modelops_celery_task_executions_total
- modelops_celery_task_failures_total
- modelops_celery_task_duration_seconds
- modelops_celery_tasks_in_progress

Celery multiprocess metrics require PROMETHEUS_MULTIPROC_DIR to be configured
before worker processes start. The exporter uses Prometheus' multiprocess
collector to expose these metrics.

Example exporter startup:

mkdir -p /tmp/modelops-celery-multiproc

PROMETHEUS_MULTIPROC_DIR=/tmp/modelops-celery-multiproc \
PYTHONPATH="$PWD" \
python -m worker.metrics_exporter

The exporter listens on 127.0.0.1:8005 by default.
MODELOPS_CELERY_METRICS_PORT can override the port.

The M9 runtime verification worker consumed only the isolated
m9_metrics_test queue. It was not a production training worker.
Do not start Celery Beat as part of this metrics test because its configured
schedule invokes deployment health checks periodically.

## Drift Detection

Endpoint:

POST /drift/detect

The request contains at least 20 samples, each with exactly 10 finite
numeric feature values.

The detector compares each current feature distribution against the
reference dataset using the two-sample Kolmogorov-Smirnov test. It applies
a Bonferroni-adjusted significance threshold across the checked features.

The response includes:

- Whether drift was detected
- Reference and current sample counts
- Number of features checked
- Drifted feature names and count
- Significance level
- Per-feature test statistics and p-values

Drift detection identifies distribution changes. It does not automatically
retrain or redeploy a model.

## Frontend Observability

The Observability page displays:

- API request totals, errors, latency and prediction outcomes
- Model-server prediction totals and average inference duration
- Drift checks, detections and total features flagged
- Celery task executions, failures and in-progress tasks
- Prometheus target health

Prometheus is accessed through the frontend Nginx proxy at /prometheus/.

Counters and histograms are cumulative since the monitored process started.
Application process restarts can reset in-memory counters. Prometheus retains
previously scraped samples in its time-series storage.
